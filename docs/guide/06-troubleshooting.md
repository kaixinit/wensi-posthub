# 常见问题与维护

## 先看消息详情的下一步操作

在“投递记录 → 详情”或“告警中心 → 查看原因与处理”查看每个渠道自己的处理指引。

| 状态 | 应怎样处理 |
| --- | --- |
| 待配置分发 | 先配置该上游的下游，再确认分发这条仍然有效的消息。 |
| 等待重试 | 查看下次尝试与截止时间；可以检测此渠道通信，恢复后自动重试，不需要重复提交。 |
| 等待微信会话 | 在绑定的微信向机器人发一句话，平台取得新会话后自动补发。 |
| 结果待核实 | 先检查实际收件；收到则登记确认。没有明确失败前不要盲目重发。 |
| 发送失败 / 投递受阻 | 按具体原因检查授权、权限、渠道启用与收件验证；修复后仅重试这个渠道。 |
| 渠道已接受 | 成功回执不等于已读；核对聊天或邮箱、垃圾邮件后，可登记实际收到。 |
| 已过期 / 已取消 | 不再自动发送；业务仍有效时核对内容后创建新的消息。 |

“检测此渠道通信”仅检查网络，不发通知、不替换投递状态、不证明账号授权或实际收件。检测后可返回原消息继续处理。成功渠道不会因其他渠道重试而再次发送。

## 微信二维码不显示或过期

在“微信渠道配置”点击“扫码绑定”重新获取。若获取失败，先查看页面错误提示，检查网络通信和代理。扫码后要在手机确认；如果出现手机授权码输入框，填写手机显示的数字。平台提示账号或环境受限时，需要先按微信提示处理，不能仅靠重复扫码保证成功。

## 微信已授权，但发送按钮不可用

用刚才扫码的微信向 ClawBot 发一句消息，等待会话自动获取，或点击“刷新微信会话”。必须是当前授权账号的会话；其他账号的消息不会替代收件人。已有其他客户端同时使用相同微信授权时，先检查原客户端的连接和消息接收情况。

## 接口返回成功，但没有通知

先看“投递记录”。HTTP 202 只代表中转台已保存；“待配置分发”需要配置下游并确认分发旧消息。“渠道已接受”仍需核对实际收件会话、群或邮箱；失败则查看目标对应的错误与告警。

## 为什么已经验证还会要求重新验证

更换收件会话、授权或连接配置后需要重新确认。没有更改的已验证渠道默认显示“已完成验证”，仅点击“重新验证收件目标”才展开验证码表单。邮箱 SMTP 授权码、手机授权验证码、渠道收件验证码和上游接入密钥用途不同；当前 QQ 流程通过会话选择指定收件人，不要求向机器人发送绑定码。

## 密钥丢失或准备停用应用

旧密钥无法找回，需在“接入配置”重置并更新上游。停用应用阻止新的 API 请求，已入队任务继续处理。删除应用会永久撤销密钥并取消尚未发送的任务；删除前会显示影响范围并要求确认。

## 代理恢复后多久补发

“等待重试”的消息持续自动尝试到投递截止时间，首次间隔 30 秒，之后间隔 60 秒；实际开始时间还受队列与网络耗时影响。重启服务后仍保留待重试任务。已经成功的下游不会重复发送；请求发出后丢失回执的“结果待核实”不能当作确定失败自动重发。

0.1.19 升级时会恢复旧版本因“3 次尝试上限”停止的未过期安全失败任务，保留原渠道与历史。已取消、成功、结果不明、渠道已变更或上游已删除的记录不会因此重新发送。

## 备份与升级

升级前备份实际数据目录中的数据库和 `config.json`。后者包含解密密钥，仅有数据库无法完整恢复连接凭据。

在项目虚拟环境中执行在线数据库备份，输出文件名必须尚不存在：

```text
python -m posthub backup --data-dir data --output posthub-backup.sqlite3
```

另行安全保存同一数据目录的 `config.json`。升级后使用原数据目录启动，核对渠道、应用和投递记录。恢复前先停服务并保留当前数据，避免覆盖唯一副本。

当前部署文件支持 Windows 11、Debian 与 Ubuntu；安装需要 Python 3.11 或更新版本。开发验收在 Windows 环境执行，Linux 实机验证范围请查看随包的 TEST-REPORT.md。

## 报告问题时准备什么

记录页面显示的版本、操作步骤、发生时间、错误提示及脱敏截图。可提供投递编号，但不要公开接入密钥、完整推送地址、机器人 AppSecret、二维码或邮箱授权码。
