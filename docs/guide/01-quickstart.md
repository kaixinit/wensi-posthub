# 快速上手

文思邮差统一接收上游应用的通知，再按每个应用的配置发送到 QQ、微信、邮箱等渠道。

**应用提交 → 中转台保存 → 按配置分发 → 查看投递回执。**

## 两个分发入口

| 入口 | 用途 |
| --- | --- |
| 上游分发 | 接入文思量化等应用，生成 API 密钥和推送地址，为每个应用配置下游渠道。 |
| 系统分发 | 在平台内手动填写消息，选择渠道，立即发送或预约发送。 |

这两个入口共用渠道管理和投递记录。上游应用仍按各自的授权范围发送，系统分发不会自动改变应用授权。

## 第一次使用

先使用默认账号 `admin` 登录。新安装的初始密码显示在安装终端，首次登录需修改；已有安装升级后继续使用原密码。登录后可随时在“账号设置”修改密码。

首次登录修改密码后，无上游接口时默认进入“接入向导”。已有用户也可从左侧进入，选择需要继续配置的上游。

1. **创建上游接口**：只填写上游名称，即可分配独立接口与密钥。可以先不选择下游。
2. **配置下游渠道**：点击“配置此上游的下游渠道”，勾选已有渠道，或“＋ 添加渠道”并完成绑定、6 位收件验证码。返回上游配置后必须保存才生效。
3. **试发并确认收件**：发送一条明确标记的接入测试。在结果中核对每个渠道，实际收到后点击“我已收到，登记确认”。平台试发不会计入真实上游推送数量。
4. **接通上游程序**：复制完整 API 地址及 JSON 示例，填入上游的 HTTP / Webhook 配置，使用 POST、application/json。由上游发送测试消息，再点击“检查接入结果”。HTTP 202 表示已保存，仍需查看每个下游的投递结果。

新接口的密钥仅临时保留在当前页面内，刷新或退出后不再展示。请在第 4 步保存地址到上游；遗失时可重置，旧密钥立即失效。向导进度来自实际配置及消息记录，刷新后可继续；修改收件配置后，旧测试不会代替新配置的验证。

也可以先跳到第 4 步接通上游。尚无下游时消息显示“待配置分发”；配置完成后，在消息详情确认业务内容仍有效，再点击“按当前配置分发”。不会自动批量重放旧消息。

上游在另一台电脑时，不要填写 127.0.0.1；使用上游能访问的平台局域网 IP 或公网域名。设置访问地址不会自动配置防火墙、frp 或 Nginx。

新事件使用新 `request_id`；同一事件重试使用相同编号和相同内容，避免重复创建。

## 三个概念

| 名称 | 用途 |
| --- | --- |
| 应用 | 上游消息来源，例如文思量化。每个应用拥有独立接入密钥与授权范围。 |
| 渠道 | 一份连接配置与具体收件目标，例如“微信1”“值班邮箱”。在渠道管理中维护。 |
| 系统分发方案 | 只用于管理员手动发送时快速带入渠道与确认设置，不关联上游。 |

机器人负责发送消息；实际收件人是选定的 QQ 用户、群、微信账号或邮箱。创建渠道后，还要在相应应用中勾选授权并保存。

> “渠道已接受”代表渠道接口返回成功回执；“收件人已确认”代表收件人完成了确认操作，或管理员根据收件人明确反馈登记收到。详情保留确认依据，接口回执不等于已读。
