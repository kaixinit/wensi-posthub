# 网络通信与访问设置

“网络通信”管理平台访问地址、下游通信检测及连接方式。代理是可选功能，不是启用消息转发的前提。页面默认打开“通信检测”，代理配置位于“连接方式 → 代理设置（可选）”，初次进入时折叠。

| 页面 | 用途 |
| --- | --- |
| 通信检测 | 检测中转台到下游服务的网络可达性，结果只代表检测时的状态 |
| 平台访问地址 | 设置上游程序和收件人访问中转台的固定地址 |
| 连接方式 | 选择直接连接或使用代理，支持按渠道配置 |

上游是否已提交请求，在“上游分发”查看接收记录；具体消息是否已被渠道接受，在“投递记录”查看。网络检测不会登录账号或发送通知，不代表账号已授权、渠道已接受或收件人已确认。填写平台访问地址不会自动配置或检测公网映射。

## 上游接入地址

| 场景 | 地址填写 |
| --- | --- |
| 上游和中转台同一机器 | `http://127.0.0.1:8787` |
| 同一局域网其他设备 | 中转台实际局域网 IP 与端口，服务需监听对应网卡且防火墙放行 |
| 通过 frp 或反向代理访问 | 上游可访问的域名、协议和外部端口，公网建议 HTTPS |

平台内部运行 Python / FastAPI / Uvicorn，不内置 Nginx。frpc 可直接连接中转台端口；需要 HTTPS 或统一站点入口时再配置外部反向代理。

“使用当前网址”会采用浏览器当前访问的协议、域名与端口生成示例。设置固定的对外地址时以固定配置为准。**修改网页中的地址不会自动更改监听端口、frp 映射或防火墙。** 当前应用按网站根路径部署，平台地址不填写额外路径。

上游不能将 `0.0.0.0` 填为访问地址。它只用于服务监听。例如在项目的 Python 虚拟环境中启动局域网服务：

```text
python -m posthub serve --host 0.0.0.0 --port 8787 --data-dir data
```

`data` 必须指向实际使用的数据目录。勿启动第二个服务进程占用相同目录。

## 默认连接方式与可选代理

打开 **网络通信 → 连接方式**，可选择“直接连接”。只有需要经过代理访问下游时，才展开 **代理设置（可选）** 并点击“添加代理”。填写名称、协议、代理主机和端口；有认证时填写用户名、密码。也可展开“粘贴完整代理地址”，该地址优先于下方独立字段。

例如，Clash 与文思邮差在同一台电脑，且实际混合端口为 7890，可填写：

| 字段 | 示例 |
| --- | --- |
| 代理名称 | 本机 Clash |
| 协议 | HTTP |
| 主机 | 127.0.0.1 |
| 端口 | 7890（以实际监听端口为准） |
| 用户名、密码 | 未开启认证时留空 |

支持 HTTP、HTTPS、SOCKS5、SOCKS5h。协议表示如何连接代理，不是目标服务的网址协议。HTTPS 网站通常也可以通过 HTTP 代理隧道访问。

“检测当前配置”不保存、不发送通知；确认配置后点击“保存代理”。代理密码加密保存，列表和诊断结果不返回密码。编辑时密码留空保持原值，勾选“清除已保存的密码”才会删除密码。

保存代理后，在默认连接方式或相应渠道中明确选择“使用代理 · 代理名称”，添加配置本身不会改变通信方式。只有设置为“跟随默认连接方式”的渠道受默认变化影响。修改共享代理会列出受影响的渠道；被引用的代理不能删除，需先调整连接方式。停用但尚未删除的渠道仍计入引用。

## 渠道独立连接方式

“渠道连接方式”显示实际生效的连接。点击“调整连接方式”，选择跟随默认、直接连接或使用代理。修改后保留已完成的收件验证、上游的下游选择及排队任务；之后新建立的网络请求采用新配置，已经发出的请求不会被撤回或重复发送。

同一个 QQ 机器人只建立一条接收连接，其收发请求统一出口。调整其中一个 QQ 渠道的连接方式时，页面会列出同机器人受影响的渠道。新增同机器人渠道自动沿用已有出口，停用其中一个渠道不会随机切换出口。

QQ、微信、企业微信、钉钉、飞书及自定义 HTTP 支持应用内代理。邮箱 SMTP 和 Apprise 扩展统一显示“系统网络”，由系统路由决定，可能经过 VPN / TUN；它们不支持应用内指定代理。使用 Clash 时，流量进入 Clash 后仍由规则选择直出或代理节点，不能仅凭“使用代理”断言走了远端节点。**直接连接不等于绕过系统 VPN / TUN，也不会自动读取 Windows 系统代理设置。**

容器内的 `127.0.0.1` 指向容器自身，需要填写容器可访问的宿主机地址。局域网代理需在代理端开启相应监听与访问权限，程序不会替你修改 Clash 或系统防火墙。

## 分步通信检测

进入 **通信检测** 可选择当前默认连接或已保存的代理，再选择 QQ、微信、企业微信、钉钉、飞书接口检测。默认选项显示实际使用的连接方式。也可点击某个渠道的“检测通信”，按该渠道的实际连接方式检测。

1. **网络检测**：仅访问服务主机，不提交通知内容。HTTP 渠道仅对服务根路径发送 HEAD，不访问自定义 Webhook 的发送路径，不携带机器人密钥。SMTP 只建立连接、检查 EHLO 和所选 TLS，不登录、不发送邮件。
2. **账号与连接**：进入渠道的“绑定与测试”，检查机器人连接、微信授权或邮箱配置。
3. **实际收件**：手动测试发送，并由收件人使用验证码确认。网络可达、渠道接受和收件确认分别显示，不混为“已送达”。

诊断显示时间、使用的出口、耗时、响应状态和处理建议。HTTP 401 / 403 / 404 / 405 表示收到了响应，不能据此认定账号授权成功；407 表示代理认证失败；429 和 5xx 提示服务异常或限流。最近记录是当时的检测快照，修改配置后需重新检测。Apprise 扩展请通过对应渠道手动测试。

## 故障处理

| 提示 | 建议 |
| --- | --- |
| 连接被拒绝 | 检查目标服务、地址和端口；使用代理时也检查代理服务 |
| 代理协商或认证失败 | 检查 HTTP / SOCKS5 协议以及账号密码 |
| 主机名解析失败 | 检查目标主机名与 DNS；使用代理时也检查代理端解析 |
| TLS 证书校验失败 | 检查系统时间及证书，不建议关闭校验 |
| 连接或响应超时 | 检查网络、路由、防火墙及渠道服务状态 |

代理故障不会自动改走直连。连接尚未建立、代理协商失败或返回 407 时，消息自动重试到投递截止：首次等待 30 秒，后续每 60 秒尝试一次。恢复代理或修正代理配置后，无需手动补发；已经成功的渠道不会再次发送。渠道明确限流也按此规则处理。连续 3 次可重试失败会产生告警，但不会停止重试，成功后该告警自动解除。请求发出后回执不明，保留为“结果待核实”，不会盲目切换代理重发。投递达到失败条件或收件确认超时后进入告警中心。

## 平台访问地址

固定的公网 / 局域网访问地址及告警接收渠道集中在 **网络通信 → 平台访问地址**。使用 frp / Nginx 时，由它们提供上游访问平台的入口；中转台访问下游服务则使用相应渠道的接口与连接方式。两个方向单独设置。文思邮差不创建 VPN 隧道，也不托管 Clash 节点订阅。

## 从旧版本升级

0.1.17 曾将旧默认代理、按渠道的单独代理转为命名代理，并升级到 schema 6；当前 0.1.25 数据库为 schema 10。QQ 机器人沿用迁移前实际接收连接的出口，并统一到该机器人的发送请求。迁移保留应用密钥、收件身份、收件验证、已配置分发范围和历史记录。

升级前备份实际数据目录中的 SQLite 数据库和 `config.json`；二者需配套保存。旧程序不能直接打开比自身支持版本更新的数据库。
